## Server contract and activation procedure

`VersionedOutcomeDefinition` retains stable instrument/version/item/option identifiers, source hash, administration mode and exact scorer/missing-policy identifiers. Items support an enumerated option or a bounded numeric response with units. `OutcomeAnswer` separates unanswered, answered, N/A, unable and not performed. An explicit numeric zero is an answer; omitted items become unanswered. A clinical scorer decides whether such a set is incomplete according to its approved policy, never a generic denominator guess.

`VersionedOutcomeRegistry` is registered only in API composition, with no packages or scorers by default. It has no patient-callable activation endpoint. To activate one instrument, engineering must add a trusted release package and exact server scorer, include approved example fixtures, and supply an approval record whose digests match the complete definition and fixture manifest. Invalid schema, missing approval evidence, nonunique versions/scorers or a failing fixture keep that version inactive. Definition order is meaningful and included in its digest; changing a label, range, version, source or policy requires renewed approval.

Before scoring, the registry rejects unknown/duplicate items, invalid states/options, mixed response types and out-of-range values. Result provenance includes definition and scorer versions, definition/source hashes and missing-policy ID. Incomplete/invalid calculations have no numeric scores. Scorer exceptions return a code without response content. This pure catalog/scoring boundary does not authorize a patient: consumers must enforce authenticated clinic/patient ownership, assigned definition/version and administration mode, note permissions and signed-record immutability before persistence.

The existing aggregate registry/service and stored scores are unchanged. `OutcomeAggregateProjection` explicitly identifies manual or legacy values with an empty answer list; no data migration or retrospective item reconstruction occurs. New response persistence, routing and signed-note snapshots belong to Plans 24, 25 and 36. Scorer tests in this PR use a synthetic two-item instrument solely to verify the framework; they are not clinical approval fixtures for any supplied form.

## Approval record to supply per instrument

- Exact source filename/hash, definition version, wording/options and any separately approved corrected source.
- Scorer ID/version and explicit answered, omitted, N/A, unable and not-performed rules, including minimum denominators and partial-domain behavior.
- Clinical approver and durable sign-off reference; approved instrument-to-patient/encounter assignment policy.
- Reproduction permission reference for the exact form/version.
- Expected item-level fixtures: complete low/high/typical, allowable missing responses, invalid/incomplete/unable cases, conditional or weighted items, and timed-trial combinations where applicable.

Do not substitute a familiar protocol for the supplied form. Do not silently fix HOOS wording, add a FAAM sports row, merge ODI variants, invent TUG aggregation or recompute historical results with a newer scorer. Each instrument can be activated independently once its own record is complete.
